## 1. 数学层

### M1 共动系还原：单参数群弹幕 = 静态迷宫 + 漂移场

任何由单参数群生成的弹幕（平移推进 / 旋转 / 螺旋 / 径向扩散），换到**随弹幕共动的参考系**里就静止了，玩家在该系中的有效速度场为：

```
u_eff(x) = u_player − v_图案(x)
```

三个可检验预测（全部来自现有参数）：

- **`wall`（7.2 m/s 推进）**：u_eff = 8.4−7.2 = **1.2 m/s**——墙缝走位其实是"以 1.2 m/s 搜索速度解静态迷宫"。这解释了为何墙类不靠速度杀人而靠缺口位置：搜索余量只有 1.2，缺口偏 2.6m 就要 2.2s，墙 36m 场地只给 5s——**数值上刚好卡死**。
- **`jumpWall`（9.4 m/s）**：u_eff = **−1.0 m/s**——共动系中玩家被匀速向后推，水平上**无法驻留**，唯一的"移动手段"只剩垂直方向。这不是设计口诀"只能跳"，是数学事实。
- **`pinwheel`（orbW=1.05 rad/s）**：切向 u_eff = 8.4−1.05r，**r>8m 后为负**——外围玩家跟不住旋转，正确解法是内收或"等缝过身"。**预测：外圈是风车的实际难点区**，可用受击位置分布验证。

> 用途：u_eff 场 = 通用难度地图。每个群生成图案注册一个 `frameVelocity(pos)` 纯函数，`?dbg` 即可画出"哪里跟得住、哪里跟不住"（→ I5）。

### M2 反应距离预算：v·τ ≤ 可视距离，否则必须 telegraph

感知-决策-运动链 τ ≈ 0.4~0.7s。弹速 v 的**无预警不可躲半径** = v·τ：

- `gaster`：15 m/s × 0.5s = **7.5m**，而炮口出生距玩家仅 3.8~5.6m → **不加预警必然不可躲**。骷髅炮口读秒动画不是美术装饰，是运动学必然——这解释了 blaster 机制为何存在。
- 佐证：`rain` 圈 1.05s ≈ 下落 0.68s+裕度；`lightning` 圈 0.35~0.55s ≈ 下落 0.28s+裕度——**现有 telegraph 时长全部 ≈ 弹的飞行时间**，隐含不变量被遵守。
- 设计规则：**瞄准类弹近生、气氛类弹远生**；注册图案时校验 `v·τ ≤ 出生距离`，不满足则强制带 telegraph 字段（→ §4 lint）。

### M3 读通道容量：已实现的验证 + 一个真问题

`H_STOPS` 在 0/0.9/1.8/3.0/4.6/7.6/12 放采样点——0~4.2m（威胁带）占了红橙黄绿青的主干，4.2~12m 压缩到蓝紫两档。**方向正确，已实现**（修正 math 文档 M3 的"建议"）。真正的问题是 **H2 的阈值错位**：颜色通道分对了吗？→ 见 H2。

### M4 深度歧义的空间分布（相机几何）

屏幕一点对应一条视线；该视线的**高度歧义量** = 视线与威胁带 [0, 3.24] 的交段长度。固定斜相机（pitch 0.40 rad ≈ 23°，`camera.ts:17`）下，歧义量随"远 + 高"增长。推论：

- 远处高空弹是可读性最贵的区域——颜色通道已全覆盖，但**地面标记的视差偏移**在远处最大；
- `projView.mix`（⑨）是现成的 A/B 旋钮：透视 → 正交混合会系统性改变歧义分布，**可做一次"投影方式 × 高度判读错误率"的受控实验**——这正是本装置该干的实验。

## 2. 实现层

### I1 仿真/演示分离：rgb 与 cls 是"半演示态"

`rgb` 每帧重算并**存在实体上**（`bullets.ts:37, 274`）；`cls` 同理（`:276`）。风险：若 `tools/equiv.mjs` 的快照含这两个字段，任何配色/文案改动都会破坏"14/14 逐位一致"。而 `cls` 只有 `'rain'` 档参与伤害路由（dmgRain 9），low/mid/high 的边界纯属演示。

**建议**：核查 equiv dump 的字段清单；把 rgb 移到渲染时重算（或 dump 只收数值字段）。此后**演示层的任何改动都 equiv-free**——H2 的阈值对齐（见下）就不再有破坏一致性的顾虑。

### I2 隧穿阈值：ball 的安全上限 ≈ 40 m/s

`ball` 判定 = 点到胶囊轴距离 − r（`bullets.ts:96-98`），无扫掠。帧采样漏检条件：帧位移 > 命中管直径 2(r+hitR) = 2×0.34 = 0.68m → **v > 40.8 m/s**（正面弦最坏情况）。当前最快 16（`sniper`）→ **2.5 倍安全裕度**。规则：ball ≤ 20 m/s 随便用；20~40 需审；>40 或缩小判定半径时强制扫掠形或子步进。

### I3 场类图案的欧拉架构已被验证

`wave`/`ripple` 的 y 与 xz 由场函数**直接赋值**、不走速度积分（`bullets.ts:224-271`）——这正是 math 文档 §5 说的"欧拉设计、拉格朗日动画"，代码里已经天然确定、天然无漂移。新场类图案（驻波/振盘/螺旋轴）**照抄此模式**：`y = f(位置, clock.elapsed)`，零新机制。

### I4 待验证三项全部关闭

见 §0 ①②③。垂直预算模型定稿：水平全控 + 2 冲量（触发不限相位的连续高度旋钮 1.37~3.01m 峰值）+ 空中水平冲刺（与跳预算独立）。

### I5 u_eff 调试面板与快照管线复用

- M1 的 `frameVelocity(pos)` + M2 的 `v·τ` 校验 + taxonomy §7 的生路计数器，三者共用 HANDOVER §10 已规划的环形快照缓冲——**回放、equiv 运行时校验、调参仪表是一套管线**，别做三遍。
- 输入录制按**边沿**录（跳/冲刺/方向变化），状态按 30Hz 存。

### I6 微观性能：不动

448 弹峰值 × 闭包排序（`render/index.ts:42`）的 GC 压力在 V8 下可忽略；`heightRGB` 121 档零分配缓存已做对。别优化没有剖析数据的热点。

## 3. 交互层

### H1 三时间尺度契约

可读弹幕必须在三个尺度上同时成立：**0.1s**（前注意特征：色相/大小/运动方向）→ **1s**（图案身份识别）→ **分钟**（图式学习）。现有通道分工：颜色=0.1s、telegraph=1s、序列编排（新招打头老招垫后）=分钟。**缺任何一层，那层就会产出"说不清"**——验收红线按层排查，而不是笼统地"加预警"。

### H2 失败归因动词化 + 阈值对齐（本篇最大落地项）

`clsName` 的分段 0.85/2.4 与物理判定带 1.37/1.87/3.24 **错位**：一颗 1.0m 的弹被判为 `mid`，提示"侧向走位"——但站立胶囊 0.44~1.16 **会被它命中**，正确首选动词是"离地"。诊断文案在说物理上不严谨的话。

**修正方案**：`clsName` 改为 1.37/1.87 分段（low=离地、mid=侧移或跳皆可、high=忌跳），与四带表逐字对齐；`clsByHeight`（历史行为）保留不动。`cls` 的 rain 伤害路由不受影响（由 kind 钉死）。前提是 I1 的 dump 字段核查通过。

再进一步：**受击诊断输出动词级归因**——命中前 0.5s 的玩家状态分类（在跳窗内吗？在圈内吗？位移方向对吗？），把验收线"三次说不清"变成可计算指标：**玩家解释与诊断归因的吻合率**。

### H3 注意力双任务（④的交互后果）

玩家同时承担"躲"与"打"（自机狙开火 0.105s cd ≈ 9.5 发/s）。攻击是躲避的**目的锚**——纯躲避没有产出感。推论：**训练场若关闭开火，认知负载结构就变了**（少一条任务线，测出的可读性偏乐观）。训练模式应有"开火开关"并默认与实战一致。

### H4 双控制系是现成的实验变量（⑤）

同一图案在笛卡尔控制 vs 极坐标控制下的可读性对照：假设旋转类图案（`pinwheel`/`counterSpiral`）在极坐标控制下更可读（控制系与图案对称系同构）。`polar.on` 代码现成，**一次对照实验就能测"控制系-图案系匹配度"**——这本身就是一篇可发表的结论。

### H5 新鲜度预算与骗术预算

- 每个新图案只引入**一个**新语法元素（新动词/新骗术/新几何）——现有编排隐式遵守，形式化为 lint；
- **骗术每阶段 ≤1**：`feint` 教会玩家"颜色会骗人"之后，第二次骗术的边际收益是负的——玩家对主读通道的信任是共享资源，透支即全通道降级。

### H6 训练场 = 间隔重复课程

按解法签名分组（taxonomy §6）+ SM-2 式间隔重排：测"解法迁移"而非"图案记忆"。实现量小（训练场已有逐图案循环与倍率，加一个排序策略即可），把训练场从图鉴升级为课程。
