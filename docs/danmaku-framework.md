## 0. 一页总览

- **五层语法**：发射层（一次 volley 长什么样）→ 子弹层（每颗弹怎么飞）→ 序列层（volley 在时间轴上怎么排）→ 表现层（玩家读到什么）→ 解法层（玩家该做什么——验收合同）。
- **两条贯穿轴**（每一层都必须回答）：
  - **高度语义**：弹在哪一带（贴地/过渡/空中/上空）、高度怎么随时间变——本作的"版本答案"轴；
  - **可读通道**：玩家靠什么读到上述信息（颜色=高度 / 地面圈 / 源锚点 / 形状 / 雷达）。
- **核心设计法：先解法后参数。** 新图案先填《解法登记表》（解法动词 + 堵死哪条旧路 + 判定锚高度 + 主读通道），再倒推发射/运动学参数。这是 HANDOVER §7.2「堵死哪条路」列的推广。
- **可读性公理**（外部研究 + 本项目验收线）：
  1. 弹越多，每颗弹越必须可预测——随机喷洒是噪音，不是弹幕；
  2. 弹幕设计的本质是**设计安全区**（mental filtering），不是设计弹；
  3. 每个图案必须声明**主读通道**，源不可见就必须有替代读法；
  4. 环境级弹幕以场地为参照，追人型以玩家为参照（v1.20 确立的判据）。

## 1. 2D 基线：五维分类

### 1.1 五维速览

| 维度 | 定义（决定什么） | 词汇 |
|---|---|---|
| **瞄准逻辑** | 弹道与玩家的关系 → **该不该动、往哪动** | 固定 / 随机 / 自机狙 / 奇数 way（不动必中）/ 偶数 way（不动反而不中）/ 狙散射 / 预判狙（打提前量）/ 追踪 / 死尸弹 |
| **几何排列** | 一组弹的空间形状 → **安全区在哪** | 直线 / 扇形 N-way / 环形 / 螺旋 / 十字星 / 雨 / 墙 / 随机出现点 |
| **运动轨迹** | 单颗弹随时间的变化 → **什么时候动** | 匀速 / 加速 / 急停（排队弹）/ 低速弹墙 / 曲 / 折曲 / 直角曲 / 分裂 / 诱导 / 反弹 / 变形 |
| **时间节奏** | volley 的释放方式 → **压迫感的呼吸** | 连续 stream / 爆发 burst / 编队 / 版底骚扰 / 组合叠加 |
| **视觉判定** | 造型与 hitbox 的关系 → **信什么** | 小玉 / 点弹（小弹大判定）/ 米弹 / 针弹 / 大玉（大弹小判定）/ 光弹 / 激光 / 魔炮（预告）|

### 1.2 排列三原语（Sparen 记法）

外部教程把几何排列收敛为三个**可组合原语**，比枚举形状更接近生成逻辑：

- **spread（扇）**：以发射点为原点、张角内均布 N 发；
- **ring（环）**：以发射点为圆心 360° 均布；
- **stack（叠）**：同形状纵深/高度重复排列（推进墙 = 横向铺满的 stack；层环 = 环的 stack）。

其余形状都是原语 + 修饰：螺旋 = ring × 角速度连续旋转；十字 = 正交双 spread；雨 = stack × 重力取向；随机点簇 = origin 侧离散化。

### 1.3 组合语法：弹幕设计的真正语言

复杂符卡 = **瞄准主轴 × 副轴叠加**。2D 经典例：自机狙+环（环锁走位、狙逼位移）；低速墙+高速点弹（墙封场、快弹收割）；固定+触壁变向+自机狙（威胁分期兑现）。

本项目已有同类组合：`lowHigh`（低扫+高扫连招，练跳）、`risenare`（地涌柱+高空爆环，双威胁）、`grenade`（读秒爆点 × 上半球散）、`wave`（推进墙 × 高度行波场）。

### 1.4 跨流派规则层（机制创新谱系）

| 作品 | 创新 | 对本项目的映射 |
|---|---|---|

## 2. 从 2D 到 3D：本项目语境的翻译

### 2.1 三个根本变化

1. **自由度不对称**：玩家被锁在地面（2D 移动 + 跳/冲刺 = 2.5 DOF），弹在真 3D。弹的威胁 = 水平可达性 × **高度带匹配**——高度差本身成为核心信息量。
2. **深度压缩**：屏幕投影丢失一维，同一屏幕点对应一条视线上的无数位置 → 高度必须**显式读通道**。本作答案：颜色=高度（`heightRGB` 每帧重算）+ 地面圈 / 源锚点（v1.21 骷髅炮口 = "看得见的源"）。
3. **判定立体化**：2D 点碰圆 → 3D 胶囊 × 弹形。**高度带即安全带**：贴地弹站立命中/跳起安全；空中带反之。

### 2.2 高度带：本作判定锚的物理推导（v2：二段跳修正）

由 `config.ts` 实测：g=27，**跳跃冲量 [9.4, 8.6]（二段跳**，`player.jumps=2`），胶囊站立 0.44~1.16，标准弹 r=0.21。关键量：

- 单跳峰值 **1.64 m**（滞空 0.70 s）；双跳峰值 **3.01 m**（滞空 1.14 s）；
- **越顶上限**（弹心高度）：单跳可越 < **1.87**；双跳可越 < **3.24**；站立安全 > **1.37**；
- **危险高度窗**：弹心 h_b 命中的条件是玩家海拔 a ∈ (h_b−1.37, h_b−0.23)，**窗宽恒 1.14 m**（胶囊 0.72 + 双弹径 0.42）。

| 带 | 弹心高度 | 站立 | 单跳 | 双跳越顶 | 语义 | 已用图案 |
|---|---|---|---|---|---|---|
| **逼跳带** | ≤ 1.37 | 命中 | 可越 | 可越 | 必须离地 | `sweepLow` 0.55、`sweepLine`、`gaster`、`stack` 中层 1.0 |
| **宽容带** | 1.37 ~ 1.87 | 安全 | 可越 | 可越 | 全解可行（教学缓冲） | `aimed` 1.55 档 |
| **单跳陷阱带** | 1.87 ~ 3.24 | 安全 | **命中** | 可越（需卡穿窗时机） | **惩罚单跳**；双跳越顶是进阶解 | `sweepHigh` 2.45、`stack` 高钉 2.35、`toho` 高臂 2.3 |
| **天外带** | > 3.24 | 安全 | 安全 | 安全 | 威胁仅来自下降 = 穿行事件 | `rain` 10.5→0、`dive` fuse −23（boss 悬停 5.4 亦在天外） |

> 对 HANDOVER §7.4 的精确化："2.30~2.35 跳起命中"应读作"**单跳**命中"——二段跳越顶是潜在进阶解。新图案选高度**先查此表**，别发明第五种语义。

### 2.3 概念映射表（2D → 3D）

| 2D 概念 | 3D 对应 | 新增设计轴 |
|---|---|---|
| 自机狙 | 水平面内瞄准玩家 | **高度独立选带**：瞄你但不打你这一层 |
| 扇形 N-way | 保留（水平面内） | 扇面可竖立 → 帘 curtain |
| 环形 | 水平环 / 竖直环 / 斜环 / 球壳 / 堆叠环 | **环平面取向**成为新参数（尚未使用） |
| 螺旋 | 平面螺旋 / 圆锥螺旋 / 极坐标旋转臂 | 旋转轴取向 |
| 墙弹 | 全宽墙推进（`wall`/`jumpWall`/`gate`） | **墙的高度剖面**：缺口 / 波动 / 跳-不跳段 |
| 雨 | 落点雨（读秒圈）/ 反雨（地面涌 `uprain`） | 落点 vs 发射点、预警通道 |
| 曲/折弹 | 重力抛物线（`fountain`）= 天然 3D 曲弹 | 垂直分量显式化 |
| 跟踪弹 | `homing`（含高度趋近 +0.8） | 追踪目标点含 y |
| 死尸弹 | 爆点弹（`mine`/`grenade` 上半球） | 爆炸立体形状 |
| 激光/魔炮 | `lasers` 实体 + `blasters` 预告 | 预警动画即读通道 |
| （2D 无） | **场类弹幕**：`ripple` y=f(r,t) 行波、`wave` 整排脉动、`sweepLine` 边界往返 | 弹幕作为"场"而非"弹群"——3D 新物种 |

### 2.4 3D 新词汇

- **体积排列**：锥 `cone`（三层锥，轴含 y 分量）、柱 `rise`/`uprain`、穹顶 `grenade`、场 `ripple`/`wave`/`sweepLine`；**未用**：帘 curtain、球壳、斜环。
- **解法动词扩容**（2D 只有横移系）：**跳** / **克制不跳** / **等波谷跳** / **离开读秒圈** / **躲爆心** / **带间穿**。
- **源可见性**成为设计参数：源可见（`gaster` 炮口）→ 读源；源不可见（落点雨）→ 必须给圈。

### 2.5 先例与公理

3D 弹幕可读的通行解 = **把玩法约束到低维流形**：Tempest 压到管面一维轨、Super Stardust HD 压到球面二维、Sin & Punishment 锁定轨道。本作"锁地面"是同源决策——代价是深度压缩，收益是**高度成为唯一需要读取的新维度**，于是可以用颜色显式编码它。这个"约束换可读"的交换是本作一切设计的元规则。

## 3. 通用框架：五层弹幕语法

### 3.0 模型与代码对应

```
序列层 ──调度──▶ 发射层 ──生成──▶ 子弹层 ──渲染──▶ 表现层
(cd/连招/编排)  (origin×arrange   (kin 管线)      (造型/颜色/预警)
                 ×aim×volley)
                                                    │
      解法层 ◀────────── 玩家通过读通道读到 ─────────┘
   (解法动词 / 堵路 / 验收)

贯穿轴：高度语义 × 可读通道（每层都要回答）
```

| 层 | 代码对应 |
|---|---|
| 发射层 | `patterns/emitters.ts`（`aimVel`/`fanShot`/`spreadShot`/`ringShot`）+ `patterns/shots.ts` 前半 |
| 子弹层 | `types.ts` 的 `Bullet` + `systems/bullets.ts` 积分/碰撞 |
| 序列层 | `patterns/sequence.ts` + `patterns/index.ts` + `systems/boss.ts` |
| 表现层 | `render/*` + `core/color.ts` + `systems/blasters.ts` |
| 解法层 | `ui/diag.ts` 受击诊断 + 设计登记表（§3.5） |

### 3.1 发射层 Emission——一次 volley 的空间与瞄准形状

**Origin（来向）**：boss 本体 / 偏移炮口（`gaster`）/ 场地锚点（`ripple`、`stack` 钉原点）/ 围玩家环布（`rise`/`rain`/`mine`/`lightning`/`grenade`/`feint`）/ 全场撒点（`downpour`）/ 玩家方向推进（`wall`/`wave`）/ **地面之下**（`uprain`，y=−2.2）/ 卫星源（`satBurst`）。
> 3D 特有：origin 的**高度**与**可见性**是独立设计参数。

**Arrange（排列）**：spread（`fanShot`，gap 可调）/ ring（`ringShot`，层数随机起始角）/ stack（纵深推进）/ cone / column / dome / **field（场）** / cluster（点簇）。
> 现状缺口：无通用锥/螺旋/极坐标发射器——`cone`、`spiral`、`pinwheel`、`ripple` 都在 shots.ts 手写；无多波次调度封装（复波靠 `later()` 手排）。

**Aim（瞄准）**：`none` 全向 / `aimed` 瞄当前位置 / `predictive` 打提前量（`sniper` 0.3s、`aimed` 0.25s）/ `offset` 瞄散（`spread` ±1.2m）/ `locked` 施法瞬间锁定（`stair`）/ `toward` 环境向（墙推向场地）/ 逐波重瞄（`cone`）。

**Volley 参数**：count / interval / 波数 / 弹速档位——慢 6~9（可读可绕：`spread`/`random`）、中 9~12（标准：`ring`/`wall`）、快 13~16（逼预判：`sniper`/`gaster`/`cone`）。

### 3.2 子弹层 Kinematics——单弹生命周期的运动学管线

现有能力（`Bullet` 字段实测）：

| 能力 | 字段/机制 | 使用者 |
|---|---|---|
| 匀速直线 | `vx/vy/vz` 默认 | 多数 |
| 重力 | `grav` | `fountain`、`grenade` |
| 追踪 | `homing`（指数趋近，目标含 +0.8 高度） | 仅 `orbit` |
| 定时变向 | `fuse` | `dive` 砸落、`feint` 改水平 |
| 边界往返 | `oscLo/oscHi`（投影反射） | 仅 `sweepLine` |
| 极坐标轨道 | `orbA/orbR/orbW`（绕过速度积分） | 仅 `pinwheel` |
| 高度行波场 | `waveU/waveP`（y 每帧重算） | 仅 `wave` |
| 径向扩散波 | `ripA/ripR/ripV` + y=f(r,t) | 仅 `ripple` |
| 指数阻尼下沉 | `kind==='smoke'` 硬编码 | `smoke` |
| 分裂 | `mineLive` → `explodeMine()` 爆 14 发 | 仅 `mine` |
| 速度调制 | 出生时按 cos(kθ) 调制 | `petal`（玫瑰线） |

**对照 2D 轨迹词汇的缺口**：无通用中途加速；无通用分裂（非 mine 硬编码）；无通用场地反弹（仅 sweepLine 私有往返）；无横向蛇形摆动；无多段持续追踪；无变形弹。

**形式化建议**（配置化的核心）：把 `kind` 硬编码分支改为**声明式修饰器管线** `kin: KinMod[]`，每项 =（激活窗口，效果函数），按序叠加于基础速度之上。匀速=空管线；`fountain`=[grav]；`dive`=[fuse→setVy]；`feint`=[fuse→retarget]。这样新运动学=新修饰器，旧图案零改动（`grav` 字段的引入方式已验证过此路径：14/14 旧图案逐位一致）。

### 3.3 序列层 Sequence——volley 在时间轴上的组织

- **现状**：4 张固定序列表（L1~L4，各 P1/P2/P3），游标逐招推进、阶段切换归零重教；`cdBase`/`cdJitter` 出招间隔；`wipeField` 换阶段清场。
- **词汇**：单招 cast / 连发 stream（`spiral` 0.072s、`pinwheel` 臂、`radial` 束内 0.088s）/ 连招 combo（`lowHigh` 低接高、`ring` 多层连发、`grenade` 错峰 0.5s、`satBurst` 双打）/ 编排规则（L4：P2 只放推进类、P3 只放环旋类、`pinwheel` 与 `sweepLine` 永不同场）/ 密度包络（`cdPerPhase` 阶梯递减）。
- **缺口**：一招内的渐强包络、玩家行为触发式（越线触发）、真正的"编队"（无杂鱼，等价物是卫星源）。

### 3.3.1 招式的连接（用户观点，2026-11-04；L4 编排的主轴）

> **原话要点**：「一个招式，结束，然后放另一个招式」还算可以，但不是最佳；
> 「一个招式没结束就叠加另一个招式」往往是不行的。
> 晶格雨和晶格叠层**都有一个全空间 FCC 的状态**，于是可以顺滑连接 —— 叠层结束后顺势接晶雨，相当不错。

换招有三种关系，只有第三种叫「连接」：

| 关系 | 玩家看到什么 | 评价 | 本项目的对应 |
|---|---|---|---|
| **硬切**（A 结束 → B 从零起手） | 清场、晶体消失、另一块长出 | 还算可以，但不是最佳 | 现状：每招 `retireOldLattice()` 0.6s 收走旧晶体 + 重新 `fccSpace()` |
| **叠加**（A 没结束就上 B） | 两片点阵混在一起 | 往往不行 | 两片全空间晶体重叠 2000+ 颗，打穿帧率且结构读不出；`retireOldLattice()` 就是为禁它 |
| **连接**（A 终态 = B 起手态） | **同一块晶体继续演化** | 最佳 | 待编排落地 |

**枢纽状态**：FCC 专场里「全空间 FCC」共享度最高 —— 16 招中 12 招以它为起手 / 稳态 / 终态
（111 / 空位 / 滑移 / 螺旋 / 聚散 / 自旋 / 叠层 / 晶雨 / 呼吸 / 声子 / 位错 / 相变）。
所以连接不是两两配对，而是**串成状态链**。另 4 招是断点（合胞 = 2×2×2 小晶体、晶轮 = 六条晶列、
齐狙 = 稀疏阵、晶锥 = 8 胞锥），要么放链首 / 链尾，要么替它们设计过渡。

**示例链（叠层 → 晶雨）**：叠层六层横扫进场、摞成静止的全空间立式 FCC = **终态**；
晶雨先以完整的全空间立式 FCC 压住场地，再逐层化雨落下 = **起手态**。
状态相同，且时间箭头天然单向（静止 → 逐层落雨）；反过来（落完场空、再让六层飞回来）就是重新起手，不顺。
**连接是有向的** —— 编排要先登记每招的「起手态 / 稳态 / 终态」，再按状态匹配串链，而不是只按机制递进或难度递增排序。

**实现层的硬约束（2026-11-04 真跑）**：同为立式 FCC / ABC 堆垛，两招的几何目前**并不相同**：

| | 层距 | 层内点距 | 层数 |
|---|---|---|---|
| 叠层 `gap=0.95` | 2.083 m | 2.553 m | 6 |
| 晶雨 `gap=0.82` | 1.799 m | 2.203 m | 7 |

相差 15.8%、层数差 1 —— **这只对「只排相邻、各自重新生成」的硬切有意义**。
一旦做成状态级接管（弹不重新生成、`lx/ly/lz` 原样保留），链首用什么几何整条链就是什么几何，
**参数自动一致、无需统一**（用户口径：点距变宽变窄、挪位置、换方向直接做即可）。
真正要做的只是让 B 跳过 `retireOldLattice()` / 重新生成，直接给 A 留下的弹与组帧加新行为。

### 3.3.2 Level 4 状态链编排表（v5.4 已落地，2026-11-04）

用户已定三项：**连接 = 状态级接管** / **16 招全量重排成状态链** / **4 招断点用硬切当休息段**。
补充用户口径：「只是让全空间点间距变宽变窄、挪个位置、换个方向，没啥好讨论的，直接做」——
所以下面不再把几何参数当对齐项。

**几何分族（跨族不能接管同一批弹）**：

| 族 | 生成函数 | 密排面 | 招式 |
|---|---|---|---|
| 轴对齐族 | `fccSpace`（U=1.9 偶宇称） | 斜置 (111) | 111 / 空位 / 滑移 / 螺旋 / 聚散 / 自旋 / 呼吸 / 声子 / 相变 |
| 立式族 | 层生成 / `fccSpaceUpright` | 水平 ABC | 叠层 / 位错 / 晶雨 |

两族晶格基不同，**链必须同族**；跨族只在链首切换时硬切。`LatticeFrame.family` 是判据。

| 段 | 状态链（链首生成一次，链内只切驱动） | 休息段（硬切） | 轮长 |
|---|---|---|---|
| P1 | 聚散 → 呼吸 → 声子 → 自旋 | 合胞 | ≈17.5s（5 招） |
| P2 | 叠层 → 晶雨 | 晶锥 | ≈15s（3 招） |
| P3 | 空位（静止漏光晶体钉场）→ 滑移 → 相变（链尾，BCC 定型后由 life 自然散场） | 螺旋 → 111 → 位错 → 晶轮 → 齐狙 | ≈34.5s（8 招） |

合计 9 招入链 + 7 招休息 = 16。P2 是用户范例：叠层终态 = 晶雨起手态。
**v5.4.1 用户复核修正**：① 位错从 P2 拿掉，叠层直接接晶雨、休息段放晶锥；
② 111 退出 P3 链 —— 它天生向下漂移扫过，`stopAt` 停住交棒时晶体已沉到 y≈−10.6 的地下，
接滑移接的是一块看不见的晶体；111 恢复完整漂移读法、进 P3 休息段，
P3 链首换成**静止的空位**（漏光晶体钉在原点，接管链从它续接）。
**v5.4.5 用户第三次指正（螺旋）**：问题不是相邻而是**接管继承** —— 螺旋接管的晶体带着滑移劈出的
上下错位，相变重排不消除错位，旋转下沉时错位跟着转，怎么排序都丑。**螺旋退出链、永远硬切**
（删掉 `latticeScrew` 的 takeover 分支，自带一整块新晶体），P3 链缩为 3 招、休息段 5 招。
教训：**「A 别接 B」若 B 的丑来自 A 留在弹上的变形，排序列解不掉 —— 只有硬切（或删）能解。**

**接管机制（已实现）**：`takeover(family, configure)` 收集场上同族 `LatticeFrame`，逐帧
`clearBulletDrive`（清 `dropAt` / `fireAt` / `tgtLx*`）+ `resetDrive`（清上一棒全部驱动，保留 `ox/oy/oz` 与弹的 `lx/ly/lz`），
再由 `configure` 设新驱动。链内招**不调** `retireOldLattice()`、**不重新** `fccSpace()`。
链首才生成并打 `family`；训练场 `state === 'training'` 不接管，保持单招独立；
4 个断点必须 `retireOldLattice()` 硬切（本批补了晶轮 / 齐狙两处遗漏）。

**关键认识：接管后几何自动一致，不需要统一参数**。弹不重新生成、局部坐标原样保留，
链首用什么点距 / 层数 / 位置，整条链就是什么 —— 叠层 / 位错 / 晶雨各自原本的
`gap=0.95 / 1 / 0.82` 只影响**被单独选中时**的退化路径，不影响链。
同理聚散 `unit 1.55→1.9` 只是让链首更饱满，`burstAt` 被 `resetDrive` 清掉所以链内不解体；
111 / 螺旋用 `stopAt` 停住交棒；空位接管瞬间删 30% 弹（漏光）；
滑移把同一批弹按切向分到 fA/fB 两个 frame；相变补 `tgtLx*`。

**实测验收（`.tmp-v53/chain.mjs`：给链首整批弹打身份标记，逐棒查还剩几颗）**：

|---|---|---|---|
| P1 | 1163 / **1163 全程不变**，1 frame | burstAt → pulseA → phononA → omega+axis | 0（合胞 63） |
| P2 | 1298 / **1298 全程不变**，6 frame upright | 静止 → rainDrop | 0（晶锥 112） |

### 3.4 表现层 Presentation——玩家读到什么

## 5. 新图案设计工作流（八步）

1. **填解法登记表**（§3.5）：解法动词？堵死哪条旧路？
2. **定高度带故事**：查 §2.2 判定锚表选带——贴地 0.45~0.55 逼跳 / 空中 2.3~2.45 罚跳 / 或跨带叙事。
3. **选主读通道**：源可见则读源；源不可见必须有圈/线替代。
4. **选发射层组合**：origin × arrange × aim × volley，优先复用现有发射器。
5. **写运动学管线**：优先用已有字段；新增字段 = 新能力，须评估旧图案逐位一致性（`grav` 引入法为范本）。
6. **定序列位置**：难度/阶段/前后招；L4 编排规则（P2 推进、P3 环旋、`pinwheel`×`sweepLine` 不同场）。
7. **数值入 config**：不散落硬编码；随机必须走 `core/random.ts`；出界阈值别动通用值（`uprain` −3.5 特例为先例）。
8. **验收**：`typecheck` → `?pat=` 训练场单招三过 → `?seed=` 复现 → `?dbg` 受击诊断无"说不清"。
