# 5D 弹幕 · 三维可读性验证装置

把玩家锁在地面一个平面上，让子弹在真正的三维空间里飞，然后回答一个问题：

> **玩家能不能读懂「那颗弹现在在哪一层」？**

这不是一个弹幕游戏。没有美术、没有养成、没有剧情，只有 54 种弹幕图案、一套高度视觉编码、一套受击诊断。
凡是「好玩」但「看不懂」的东西，优先级都排在后面。

- 当前版本：**v1.21**（最近一次提交）；工作区含未提交的 **Level 4 FCC 晶格专场**、渲染性能改动与 **v5.3 三新招（晶胞 / 层单位）**
- 技术栈：Vite + TypeScript，**零运行时依赖**（canvas 2D + 手写透视投影）
- 交接文档：**[HANDOVER.md](./HANDOVER.md)**（模块地图、数值表、图案清单、已知问题、路线图）
- 研究笔记：`docs/` **五篇** —— [弹幕的基础单位](./docs/danmaku-unit.md)（设计观点保真记录）/ 框架 / 分类学 / 数学 / 灼见（审计口径见各篇末尾注记）
- 历史基线：`archive/v0.6-single-file.html`（重构前的单文件版本，1:1 对照用）

## 这个项目是干什么的

三条研究线，各自对应代码里的入口：

| 研究目的 | 怎么用 | 从哪里改 |
|---|---|---|
| **测试玩法** | 直接打，看能不能读懂、躲不躲得开 | `src/config.ts`（所有数值） |
| **研究机制** | 单独跑某个图案、固定种子复现、dump 快照对比 | `src/patterns/`、`?pat=` `?dbg=1` |
| **玩家验证** | 3 局 × 受击诊断 + 结算页的受击分布 | `src/ui/diag.ts`、`src/systems/bullets.ts` |

验收线（原型的判断标准，不是感觉）：

> 玩 3 局，每局结束后问：**每次被击中时，你是否知道「为什么被打中」？**
> 三次里只要有一次说不清，可读性系统就不合格。

## 视觉编码

### 颜色 = 当前高度（连续）

| 高度 | 0 m | 0.9 | 1.8 | 3.0 | 4.6 | 7.6 | 12 m |
|---|---|---|---|---|---|---|---|
| 颜色 | 红 | 橙 | 黄 | 绿 | 青 | 蓝 | 紫 |
| 怎么躲 | 起跳 | 侧走 | 侧走 | — | 别起跳 | 从下方穿 | 从下方穿 |

颜色只由**这一刻的高度**决定，所以一颗弹从高空落下来会一路变色（紫→蓝→青→黄→红）。
你读到的永远是它现在在第几层，而不是它出生时贴的标签。

### 其它读 Aid

- **地面亮圈**：即将落下的东西（俯冲弹悬停读秒 / 地雷读秒 / 地涌升起），靠「离开圈」躲
- **俯视雷达**（`M`）：颜色同样 = 高度，**实心 = 低空，空心 = 高空**
- **轨迹线**（`T`）：拖尾 / 预测虚线 / 关
- **受击诊断**：每次被打中记录「被什么打中 / 命中高度 / 怎么躲」，只留最近 4 条（`config.ts: DIAG_KEEP`）

> 这些读 Aid 的开关都在**暂停卡的设置面板**里（暂停即见），也可以在对局里直接按快捷键 G/H/K/M/T。

## 难度

起始页可以选四档。四档之间**只差图案池、出招密度、弹速**，玩家血量、判定、场地完全一致 —— 对比时只有一个变量在动：

| | Level 1 | Level 2 | Level 3 | Level 4 |
|---|---|---|---|---|
| 图案 | 16 种 | 21 种（多 5 种「侧移无效」的） | 27 种（形状弹幕 · 微操） | **16 种晶格系（FCC 专场）** |
| 出招间隔 | 基数 1.85s | 基数 1.42s（约 1.3 倍密度） | 基数 1.12s（约 1.7 倍密度） | 基数 1.02s；晶格招用 `holdCd` 占台 6~10s |
| 敌方弹速 | 1.0× | 1.1× | 1.18× | 1.15× |
| 适合 | 第一次玩 / 采基线数据 | 已经能无伤过 Level 1 | 已经能无伤过 Level 2 · 想练微操 | 想练读全空间三维点阵 |

> Level 4 已改成 **FCC 晶格专场**：序列里只放 16 招晶格系，非晶格招全部移出该难度。
> 旧的 11 招「跳跃必要性」仍保留在代码与 `ALL_PATTERNS` 里，训练场可单独选，只是不进 L4 序列。

Level 2 的 5 个新图案按同一条原则设计：**能靠侧移解决的，不算难**。

| 图案 | 它堵死了哪条路 | 正解 |
|---|---|---|
| **跃墙** | 横跨整场 36m、没有缺口，速度比玩家快 | 只能跳。低（0.55m）→ 高（3.1m）→ 低，三波卡起跳节奏 |
| **预判狙** | 按你的速度打提前量，三个高度同时来 | 站着不动会被三发一起命中，必须一直变向 |
| **闸门** | 两道墙缺口错开 4.4m | 穿过第一道后必须立刻横移到第二个口 |
| **涌裂** | 地涌升到 2.9m 炸开一圈 | 起手就拉开距离，贴脸站桩会被柱子和环同时处理 |
| **假坠** | 紫色高空弹落到 1.78m 突然改水平冲刺 | 颜色在说谎 —— 读运动，不是读颜色 |

> 「跃墙」是专门为"侧移能解决一切"这个漏洞加的：墙横跨全场、无缺口、比玩家快，
> 唯一的解是跳。第三波高墙（3.1m）又逼你不能乱跳 —— 跳早了会被它打中。

Level 3 换了一套玩法主题：**形状弹幕 · 微操穿梭**（参考东方）。
全部是规则形状 —— 花瓣、光芒、点阵雨、喷泉弧线、上升柱、锥形喷射，
缝隙清晰、有节奏，靠在缝里挪一小步过。**墙类一概不进**（跃墙 / 闸门 / 墙缝都排除）。

| 图案 | 它长什么样 | 正解 |
|---|---|---|
| **花瓣环** | 径向速度按玫瑰线调制，俯视呈五瓣/六瓣花 | 沿花瓣之间的沟挪，别横穿 |
| **放射光芒** | 多束光线从 boss 射出，束与束低/高交替 | 挪到两束之间的扇形缝 |
| **全图雨** | 满场亮圈读秒后落雨，落点按面积均匀撒开 | 看圈挪半步 —— 别跑，跑会撞下一批 |
| **喷泉** | 从 boss 脚下斜抛出一圈圈抛物线弹，落点成环带 | 贴 boss 或退到 12m 外都安全 |
| **反雨** | 弹幕在**地面的背面**（负 y）坠向地面，穿过地板升到约 1.5m 结束 | 横移出柱，或跳过它的顶 |
| **放射锥** | 朝你的方向喷锥状弹幕，逐波重瞄 | 贴着锥边持续微移 |

> 喷泉是第一种**带重力**的弹（`Bullet.grav`）：升的时候红→青、落回来青→红，
> 颜色就是它在弧线哪一段的直读。全图雨刻意压着密度（每波 16 颗、落速偏慢、颗颗有亮圈），
> 难在「同时读多个圈」，不在反应速度。

Level 4 已改成 **FCC 晶格专场**：16 招全是同一块全空间面心立方点阵的不同单位 / 运动 / 缺陷 / 相变。
晶体填满「场地圆柱 × 高 −2~10.5m」，约 1000~2700 颗，玩家从头到尾在晶体内部 ——
读的是「我现在站在哪个网眼里、下一层网眼错到哪去」，不是「要不要跳」。

| 段 | 状态链（→ 同一批弹继续演化） | 休息段（‖ 硬切） | 轮长 |
|---|---|---|---|
| P1 · 轴对齐族 | 聚散 → 呼吸 → 声子 → 自旋 | 合胞 | ≈17.5s（5 招） |
| P2 · 立式族 | **叠层 → 晶雨** | 晶锥 | ≈15s（3 招） |
| P3 · 轴对齐族 | 空位（钉场）→ 滑移 → 相变 | 螺旋 → 111 → 位错 → 晶轮 → 齐狙 | ≈34.5s（8 招） |

**v5.4 编排主轴 = 招式的连接**（见 [docs/danmaku-framework.md](./docs/danmaku-framework.md) §3.3）：
不是「一招结束再放另一招」的硬切，也不是两片晶体叠加，而是**链首生成一次晶体、链内招接管同一批弹**，
只切换组帧上的驱动字段。链内不 retire、不重新生成，弹数与局部坐标全程不变（真跑见 §3.3.2）；
只有链首切换和 4 个休息段才清场。轴对齐族与立式族几何不同，跨族只在链首硬切；训练场保持单招独立、不接管。

**v5.3 三新招按「弹幕的基础单位」组织**（见 [docs/danmaku-unit.md](./docs/danmaku-unit.md)）：
合胞与晶锥的单位是**单个晶胞**（14 点：8 顶角 + 6 面心），叠层的单位是**一层**；
弹数（63 / 1298 / 112）与单位数（1 胞 / 1 层）不在一个层面上。

每招仍声明 `holdCd`（6~10s），但**链内换招不再清场**；换阶段不打断进行中的招式。
生成函数 `fccSpace` / `fccSpaceUpright` / `fccCell` 的 unit / radius / skip / 层数 / 高度带全带默认值 ——
难度就是参数组合，不是重写招式。

## 出招顺序（固定）

默认**不再随机抽**——随机意味着三次测试跑的不是同一套弹幕，结论不可比。
每个阶段走一条固定序列（`src/patterns/sequence.ts`），阶段切换时回到该阶段第一招：

**Level 1**：

| 阶段 | 顺序 |
|---|---|
| P1 | 贴地扫 → 弥散 → 地涌 → 环形 → 阶梯 |
| P2 | 高空扫 → 落点雨 → 卫星 → 俯冲 → 低接高 → 贴地扫 → 弥散 → 地涌 → 环形 → 阶梯 |
| P3 | 墙缝 → 激光 → 追踪 → 地雷 → 螺旋 → 双螺旋 → 高空扫 → 落点雨 → 卫星 → 俯冲 → 低接高 → 贴地扫 → 弥散 → 地涌 → 环形 → 阶梯 |

**Level 2**：

| 阶段 | 顺序 |
|---|---|
| P1 | 跃墙 → 贴地扫 → 预判狙 → 闸门 → 涌裂 → 弥散 |
| P2 | 跃墙 → 预判狙 → 闸门 → 假坠 → 涌裂 →（Level 1 的 P2 全套） |
| P3 | 跃墙 → 闸门 → 预判狙 → 假坠 → 涌裂 → 螺旋 → 双螺旋 →（Level 1 的 P3 全套） |

**Level 3**（先教形状阅读，再教环境弹幕，最后全混合）：

| 阶段 | 顺序 |
|---|---|
| P1 | 花瓣环 → 环形 → 放射光芒 → 螺旋 → 喷泉 |
| P2 | 全图雨 → 放射锥 → 花瓣环 → 双螺旋 → 喷泉 → 放射光芒 → 环形 → 螺旋 |
| P3 | 反雨 → 放射锥 → 全图雨 → 花瓣环 → 喷泉 → 螺旋 → 双螺旋 → 放射光芒 → 环形 → 假坠 → 卫星 |

**Level 4 · FCC 晶格专场 · 状态链**（16 招；轮长 P1≈17.5s / P2≈15s / P3≈34.5s。「→」= 接管同一批弹，「‖」= 硬切休息段）：

| 阶段 | 顺序 |
|---|---|
| P1 | 晶格·聚散 → 晶格·呼吸 → 晶格·声子 → 晶格·自旋 ‖ 晶格·合胞 |
| P2 | 晶格·叠层 → 晶格·晶雨 ‖ 晶格·晶锥 |
| P3 | 晶格·空位 → 晶格·滑移 → 晶格·相变 ‖ 晶格·螺旋 → 晶格·111 → 晶格·位错 → 晶轮 → 晶格·齐狙 |

> 随机池 `D4_POOL` 由序列去重生成，`?seq=random` 自动跟随专场。
> 换阶段只切 phase/seq，不砍 `holdCd`、不清场 —— 进行中的晶体招会自然走完。

排序逻辑（Level 1~3）：先教「跳 / 读三层 / 横移」，再教「别跳 / 离圈 / 认发射源」，
最后上需要读全局的弹墙与激光；Level 2 每阶段以「跃墙」开场。Level 4 单独按上表的晶格机制递进。

- 本局实际出过的招记在 `boss.cast`（最多 48 条），`__dbg.history` 可读
- `?seq=random` 退回 v0.6 的随机抽（对照「固定顺序是否改变了难度曲线」）
- `?seed=N` 固定整局随机源：**配合 `?t=N` 才能逐位复现**（真人对局帧时长不固定，做不到逐位）

## 训练场

从说明页点「训练场」，或 `?train=1` 直接进。和正常对局的区别只有四条：

| 项 | 对局 | 训练场 |
|---|---|---|
| 计时 | 2 分钟倒计时 | 正计时，不计时 |
| boss | 掉血、分三阶段 | 不掉血（只有受击闪白） |
| 玩家 | 会死 | 不扣血，受击只记诊断 |
| 出招 | 固定序列，按 boss 节奏 | 选中哪招就循环哪招，每 2.8 秒一次 |

**选招式是暂停时做的事**，不是常驻面板 —— 练习时画面和正常对局一样干净：

1. 按 `P`（手机上点右侧「暂停」）暂停，暂停卡里会多出「选招式」区：54 格 + 弹速 0.5×/1×/1.5×
2. 点一格 → 立刻换成这一招并自动继续；调弹速则留在暂停卡里，方便先设速度再选招
3. 「再来一发」清场重放当前招，用来反复看同一个起手

训练场和对局一样会锁定鼠标（桌面端），所以转视角就是移动鼠标；暂停时会自动解锁，否则点不到卡片。

### 性能口径（必读）

项目早期文档里的 `60.4 fps`、`39.7 fps` 全部来自 **headless Chromium `--disable-gpu` 软件渲染**。
同一场景（1440×900、`?diff=4`、1988 颗「晶格·聚散」、固定 seed）在软渲染下约 **155 ms/帧**，
在本机真 GPU（Intel UHD D3D11）下约 **6.4 ms/帧**，差 24 倍。

> **性能结论必须标注 renderer。** 软渲染数字只能用于同口径 A/B，不能当达标线。

先 `npm run dev`，再 `npm run perf`（`tools/perf.mjs`）：固定随机源、接管 rAF 让 dt 恒定、
统计单帧 JS 耗时与 canvas 调用数，输出 `gpuRenderer` 与 PASS/FAIL。默认目标 **11.1 ms/帧**
（90 fps 等价 —— 60Hz 屏幕的 rAF 上限是 60，所以用单帧耗时而不是帧率计）。
常用参数：`--pat lattice111 --frames 180 --target 11.1 --shot .tmp-perf/shot.png`；
服务不在默认 5173 端口时加 `--port <端口>`，加 `--gpu=0` 才退回软渲染口径。

2026-11-04 实测（真 GPU）：**mean 6.4 / p50 4.1 / p95 10.7 / max 12.1 ms**，达标。
关键结论：晶格大弹那层独立 64px 辉光是填充率大头，改成只画合成贴图后单帧 30.4 → 6.4 ms；
而把雷达按颜色批绘砍掉 23% canvas 调用，帧时间**没有可测收益** —— 这个场景填充率主导，不是 draw call。

**v5.3 复测（真 GPU，同一台 Intel UHD D3D11）**：晶格·自旋填满后 2713 颗，
`npm run perf -- --pat latticeSpin --warm 120 --frames 180` → **mean 14.95 / p50 6.3 / p95 12.9 / max 413.2 ms，FAIL**（目标 11.1）。
两次复跑都出现约 400ms 的离群帧；去掉最大离群值 mean 仍约 12.7ms，**不是单纯抖动，密度确实把 p95 推过了线**。
这是「填满整个空间」的代价。**用户 2026-11-04 晚确认「自旋目前还好，先这样吧」—— 保留 2713 颗、不降级、不改点距**；
这里的 FAIL 是已知且已接受的口径，不是待修的 bug。若日后要压帧时间，一行折中：只给自旋传 `unit: 2.1`
（最近邻 2.69 → 2.97m）→ 1977 颗，回到 1988 颗基线水平，且仍覆盖圆盘 R=18 + 轴向 ±18 的全空间。

**晶锥：3³ → 2³ 的性能对照（真 GPU，同口径，`--pat latticeCone --warm 60 --frames 120`）**：

| 版本 | 晶胞 / 弹数 | canvas 调用/帧 | mean | p50 | p95 | max | 结论 |
|---|---|---|---|---|---|---|---|
| 3³（旧） | 27 / 378 | ≈2.9 万 | 28.8 | 4.4 | **182.3** | 1168.8 | FAIL，约 5% 帧百毫秒级卡顿 |
| **2³（现）** | **8 / 112** | **8961** | **2.181** | 1.9 | **6.6** | 8.4 | **PASS** |

3D 形状每颗约 78 次绘制调用（球体约 4 次），**晶胞数就是绘制量的主旋钮** ——
用户复核后把 3³ 改成 2³，锥状层次仍保留（1 中轴 + 3 内环 + 4 外环），卡顿消失。
`ConeOpt.rings` 留了回退 27 胞分布的接口。

**v5.4 状态链口径（真 GPU，同口径）**：链内每招都是同一批弹（P1 / P3 1163 颗、P2 1298 颗），
`npm run perf -- --pat latticeBurst --warm 90 --frames 120` → 1163 颗、canvas 5167 次/帧、
mean **4.32** / p50 2.6 / p95 **10.0** / max 10.8 ms，**PASS**。
链内换招不重新生成弹，帧时间不会因「连接」而叠加。
